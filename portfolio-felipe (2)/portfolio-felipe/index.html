O Ensino Médio também me ensinou a programar

Programar não é só escrever código. Cada área do Ensino Médio contribuiu de um jeito diferente para a forma como eu penso, organizo e resolvo problemas. Aqui conto como isso aconteceu comigo.

01

Ciências Humanas

Em História, Geografia, Sociologia e Filosofia eu aprendi que todo problema tem um contexto. Antes de dar uma resposta, a gente precisa entender quem está envolvido, o que causou a situação e quais são as consequências. Hoje eu faço exatamente isso antes de abrir o editor de código: pergunto quem vai usar o sistema e qual problema real ele precisa resolver.

O pensamento crítico que treinei analisando textos, notícias e debates também me ajuda a não aceitar a primeira solução que aparece. Eu comparo alternativas, penso em quem pode ser prejudicado por uma decisão e tento enxergar o lado de pessoas diferentes de mim — o que é essencial para criar sites acessíveis e fáceis de usar.

Entender o comportamento humano me mostrou que tecnologia é feita para pessoas. Um botão no lugar errado, um texto confuso ou um formulário longo demais fazem o usuário desistir. Por isso, quando desenvolvo uma interface, penso primeiro na experiência de quem está do outro lado da tela.

Análise de problemas Foco no usuário Acessibilidade Ética e dados

// Antes de programar: entender o contexto
const problema = {

Interpretar um problema social é muito parecido com levantar os requisitos de um sistema: as duas coisas começam ouvindo as pessoas.
02

Ciências da Natureza

Física, Química e Biologia me apresentaram o método científico: observar um fenômeno, levantar uma hipótese, testar e analisar o resultado. Quando um código meu não funciona, eu sigo o mesmo caminho. Observo o erro, imagino o que pode estar causando, faço uma alteração pequena e confiro se a hipótese estava certa.

Nas aulas de laboratório aprendi a mudar uma variável por vez para saber o que realmente influenciou o experimento. Na programação, isso virou uma regra para depurar: não altero cinco coisas de uma vez, senão não descubro qual delas resolveu — ou qual criou um problema novo.

Também aprendi a registrar os resultados e a repetir os testes. Isso se conecta diretamente com testar um sistema em situações diferentes: campos vazios, valores negativos, telas pequenas. Um algoritmo, assim como um experimento, só é confiável depois de ser testado.

Observação Hipóteses Depuração Testes
experimento.test.js
// Hipótese: o cálculo quebra com valores negativos
function testarDesconto() {
  const resultado = aplicarDesconto(-50, 10);

  // Resultado esperado x resultado observado
  console.assert(resultado >= 0,
    "Hipótese confirmada: precisa validar a entrada");
}

testarDesconto(); // repetir até o teste passar
Depurar um código é aplicar o método científico: observar, formular hipóteses, testar e concluir.
03

Matemática

A Matemática é a área que mais aparece no meu código, mesmo quando eu não percebo. Quando estudei funções, aprendi que existe uma entrada, uma regra e uma saída — e é exatamente assim que uma função em JavaScript ou PHP funciona. As incógnitas da álgebra viraram variáveis que guardam valores e mudam durante a execução.

O raciocínio lógico das questões de “se… então” me ajudou a entender estruturas condicionais como if e else. Já as sequências e os padrões que aparecem em progressões me prepararam para as estruturas de repetição, como for e while, que executam a mesma regra várias vezes.

Mas o principal foi aprender a resolver problemas em etapas: ler o enunciado, separar os dados, escolher a operação certa e conferir o resultado. Um algoritmo nada mais é do que essa resolução escrita de um jeito que o computador entende.

Raciocínio lógico Funções e variáveis Condições Repetição
media.js
// f(notas) = soma das notas ÷ quantidade
function calcularMedia(notas) {
  let soma = 0;            // variável

  for (const nota of notas) { // repetição
    soma += nota;            // operação
  }

  const media = soma / notas.length;
  return media >= 6        // condição
    ? "Aprovado"
    : "Recuperação";
}

calcularMedia([7.5, 5, 8]); // "Aprovado"
Uma função matemática e uma função de programação têm a mesma ideia: entrada → regra → saída.
04

Linguagens

Em Língua Portuguesa aprendi que interpretar um texto é diferente de apenas lê-lo. Essa habilidade faz muita diferença quando recebo o enunciado de uma atividade ou o pedido de um cliente: preciso entender o que está escrito e também o que a pessoa realmente quer dizer.

A redação me ensinou a organizar as ideias com começo, meio e fim. Eu levo isso para o código: dou nomes claros para variáveis e funções, separo os arquivos por responsabilidade e escrevo comentários e documentação, como um README, para que outra pessoa consiga entender o que fiz.

Já o Inglês está presente em quase tudo na programação — nas palavras reservadas das linguagens, nas mensagens de erro e nas documentações oficiais. E as aulas de Artes e Educação Física também ajudaram: a primeira na percepção de cores e composição visual, a segunda no trabalho em equipe. No fim, um bom sistema também é uma forma de comunicação com o usuário.

03 · Tendências Tecnológicas

Tecnologias que estão moldando o futuro

Um resumo técnico — e direto ao ponto — sobre quatro áreas que todo desenvolvedor precisa conhecer: cibersegurança, blockchain, automação e robótica, e edge computing.

Tendência 01

Cibersegurança

Cibersegurança é o conjunto de práticas, tecnologias e processos usados para proteger sistemas, redes e dados contra acessos não autorizados, ataques e vazamentos. Ela se apoia em três pilares: confidencialidade (só quem deve acessa), integridade (os dados não são alterados indevidamente) e disponibilidade (o sistema funciona quando precisa).

Proteção de dados

Envolve controlar quem acessa as informações, fazer backups e coletar apenas o necessário. No Brasil, a LGPD (Lei 13.709/2018) define regras para o tratamento de dados pessoais.

Criptografia

Transforma dados legíveis em um formato ilegível sem a chave correta. Está no HTTPS (TLS), no armazenamento de senhas com hash (como bcrypt) e em mensageiros com criptografia de ponta a ponta.

Autenticação

Confirma que o usuário é quem diz ser. Vai além da senha: autenticação em dois fatores (2FA), biometria e chaves de acesso (passkeys) tornam o login muito mais seguro.

Principais ameaças

  • Phishing: golpes que imitam empresas para roubar dados.
  • Ransomware: sequestra arquivos e pede resgate.
  • Injeção de SQL e XSS: exploram entradas não validadas.
  • Senhas fracas e reutilizadas.

Importância para desenvolvedores

Segurança começa no código: validar toda entrada do usuário, usar consultas preparadas no banco de dados, nunca guardar senhas em texto puro, manter dependências atualizadas e não expor credenciais no repositório.

Segurança por padrão

O ideal é pensar em segurança desde o planejamento (security by design), aplicando o princípio do menor privilégio: cada usuário e cada parte do sistema acessa apenas o que realmente precisa.

Tendência 02

Blockchain

Blockchain é um registro digital distribuído, em que as informações são organizadas em blocos encadeados. Cada bloco depende do anterior, formando uma corrente que pode ser verificada por todos os participantes da rede e que é extremamente difícil de alterar depois de gravada.

Funcionamento dos blocos

Cada bloco armazena um conjunto de dados (como transações), a data de criação, o seu próprio hash — uma “impressão digital” calculada a partir do conteúdo — e o hash do bloco anterior. Se alguém altera um bloco antigo, o hash dele muda e todos os blocos seguintes deixam de bater.

Descentralização

Em vez de um único servidor controlar os dados, várias cópias do registro ficam espalhadas por computadores da rede (os nós). Um novo bloco só é aceito quando os participantes chegam a um acordo, por meio de um mecanismo de consenso como Proof of Work ou Proof of Stake.

Segurança e transparência

A combinação de criptografia, encadeamento por hash e consenso torna o histórico praticamente imutável. Em blockchains públicas, qualquer pessoa pode auditar as transações. Ainda assim, a tecnologia não elimina riscos como golpes, perda de chaves privadas ou falhas em contratos inteligentes.

Aplicações práticas

  • Criptomoedas, como o Bitcoin.
  • Contratos inteligentes que se executam sozinhos.
  • Rastreamento de produtos na cadeia de suprimentos.
  • Registro e verificação de certificados e documentos.
Tendência 03

Automação e Robótica

Automação é usar tecnologia para executar tarefas com pouca ou nenhuma intervenção humana. Robótica é a área que projeta máquinas capazes de perceber o ambiente por meio de sensores, tomar decisões com um controlador e agir no mundo físico por meio de atuadores, como motores.

Automação de processos

No mundo digital, a RPA (automação robótica de processos) usa “robôs de software” para repetir tarefas como preencher planilhas, emitir notas e enviar e-mails. Integrações entre sistemas — como o envio automático de notificações deste portfólio — também são automação.

Robótica industrial

Braços robóticos fazem soldagem, pintura, montagem e embalagem com precisão e velocidade constantes. Os cobots (robôs colaborativos) trabalham ao lado de pessoas com sensores de segurança. É um dos pilares da Indústria 4.0.

Inteligência artificial aplicada

Com IA, as máquinas deixam de apenas seguir regras fixas e passam a reconhecer padrões. Visão computacional identifica peças com defeito, modelos de aprendizado de máquina preveem falhas em equipamentos e assistentes respondem a perguntas em linguagem natural.

No cotidiano e nas empresas

  • Robôs aspiradores e casas inteligentes.
  • Caixas de autoatendimento e chatbots.
  • Armazéns com robôs que separam pedidos.
  • Máquinas agrícolas guiadas por GPS e drones.
Tendência 04

Edge Computing

Edge Computing (computação de borda) é um modelo em que os dados são processados perto de onde são gerados — no próprio dispositivo, em um gateway local ou em um pequeno servidor próximo — em vez de viajarem todos até um data center distante. A “borda” é a extremidade da rede, onde estão sensores, câmeras, celulares e máquinas.

Edge Computing x Cloud Computing

Os dois modelos não competem: eles se complementam. A borda resolve o que precisa de resposta imediata, e a nuvem cuida do que exige muito armazenamento e poder de processamento.

AspectoEdgeCloud
Onde processaPerto da fonte dos dadosData centers centralizados
LatênciaMuito baixa (milissegundos)Maior, depende da distância
Uso de internetEnvia só o essencialEnvia todos os dados
CapacidadeLimitada ao hardware localPraticamente ilimitada
Melhor paraDecisões em tempo realAnálises e armazenamento em larga escala

Vantagens

  • Menor latência: respostas quase instantâneas.
  • Economia de banda: menos dados trafegando pela rede.
  • Funciona com conexão instável ou até offline.
  • Privacidade: dados sensíveis podem ficar no local.

Aplicações práticas

  • Carros autônomos que precisam frear em frações de segundo.
  • Indústrias que monitoram máquinas em tempo real (IoT).
  • Câmeras inteligentes que analisam imagens no próprio aparelho.
  • Redes 5G e jogos com baixa latência.

Pixel Store

E-commerce de games e periféricos — consoles, jogos, periféricos e acessórios — desenvolvido em PHP com banco de dados MySQL. O sistema tem área do cliente e painel administrativo, com compras simuladas (nenhuma cobrança real é feita).

  • Vitrine com busca, filtro por categoria e ordenação por nome, preço e novidades.
  • Cadastro e login com senhas protegidas por password_hash().
  • Carrinho, checkout (Pix, boleto ou cartão simulados) e histórico “Meus pedidos”.
  • Painel admin: receita, pedidos, estoque baixo e cadastro/edição de produtos.
  • Segurança: consultas preparadas (PDO), tokens CSRF e credenciais em arquivo .env.
